# API Contract

Base URL: `/api` · Content type: `application/json` · Timestamps: ISO-8601 UTC (`2026-09-25T10:15:30Z`)

An OpenAPI document is generated by springdoc at `/v3/api-docs` and Swagger UI at `/swagger-ui.html`. This file is the design contract; the generated OpenAPI must match it.

## 1. Endpoint summary

| Method | Path | Purpose | Req |

| `GET` | `/api/tickets` | List / search / filter tickets | FR-02, FR-07, FR-08 |
| `GET` | `/api/tickets/{id}` | Get ticket details | FR-03 |

## 2. Resources

### 2.1 `TicketResponse`

```json
{
  "id": 42,
  "title": "Cannot log in to portal",
  "description": "User gets 500 after entering password.",
  "priority": "HIGH",
  "status": "IN_PROGRESS",
  "assignee": "Priya",
  "allowedTransitions": ["RESOLVED", "CANCELLED"],
  "commentCount": 3,
  "createdAt": "2026-09-25T10:15:30Z",
  "updatedAt": "2026-09-25T11:02:00Z",
  "version": 2
}
```

`allowedTransitions` is computed from `state-machine.md` so the UI never hard-codes the rules.

### 2.2 `TicketSummaryResponse` (list item)

Same as `TicketResponse` without `description` and `allowedTransitions`.

### 2.3 `CommentResponse`

```json
{ "id": 7, "ticketId": 42, "author": "Rahul", "body": "Reproduced on staging.", "createdAt": "2026-09-25T10:20:00Z" }
```

### 2.4 `PageResponse<T>`

```json
{ "content": [ ... ], "page": 0, "size": 20, "totalElements": 57, "totalPages": 3 }
```

## 3. Error format

All errors (4xx/5xx) use RFC 9457 Problem Details (`application/problem+json`) with project extensions:

```json
{
  "type": "about:blank",
  "title": "Validation failed",
  "status": 400,
  "detail": "One or more fields are invalid.",
  "instance": "/api/tickets",
  "code": "VALIDATION_FAILED",
  "timestamp": "2026-09-25T10:15:30Z",
  "errors": [
    { "field": "title", "message": "Title must be between 3 and 200 characters." },
    { "field": "priority", "message": "Priority must be one of LOW, MEDIUM, HIGH, CRITICAL." }
  ]
}
```

| Code | HTTP | When |
|------|------|------|
| `VALIDATION_FAILED` | 400 | Bean validation failure, bad enum value, bad query param, malformed JSON |
| `TICKET_NOT_FOUND` | 404 | No ticket with that id |
| `INVALID_STATUS_TRANSITION` | 409 | Transition not allowed by state machine |
| `TICKET_NOT_EDITABLE` | 409 | Update/comment on `CLOSED` or `CANCELLED` ticket |
| `CONCURRENT_MODIFICATION` | 409 | `version` mismatch (optimistic lock) |
| `INTERNAL_ERROR` | 500 | Unexpected error. `detail` is generic; **no stack traces or SQL** in the body. |

Rules:
- `message` strings are written for end users (the UI displays them directly).
- `errors` is present only for `VALIDATION_FAILED`.
- A single `@RestControllerAdvice` produces all error bodies.

## 4. Endpoints

### 4.1 Create ticket — `POST /api/tickets`

Request:
```json
{ "title": "Cannot log in", "description": "500 after password", "priority": "HIGH", "assignee": "Priya" }
```
- `assignee` optional. `status`, `id`, timestamps in the body are ignored.

Responses: `201 Created` + `Location: /api/tickets/{id}` + `TicketResponse` (status `OPEN`) · `400 VALIDATION_FAILED`

### 4.2 List tickets — `GET /api/tickets`

| Query param | Type | Default | Notes |
|-------------|------|---------|-------|
| `q` | string | — | Keyword, case-insensitive substring of title or description; max 100 chars; blank = no filter |
| `status` | enum | — | Exact match; invalid value → 400 |
| `page` | int | 0 | ≥ 0 |
| `size` | int | 20 | 1–100 |
| `sort` | string | `createdAt,desc` | Allowed fields: `createdAt`, `updatedAt`, `priority`, `title` |

Example: `GET /api/tickets?q=login&status=OPEN&page=0&size=20`

Responses: `200 OK` + `PageResponse<TicketSummaryResponse>` (empty `content` when nothing matches — never 404) · `400 VALIDATION_FAILED`

### 4.3 Get ticket — `GET /api/tickets/{id}`

Responses: `200 OK` + `TicketResponse` · `404 TICKET_NOT_FOUND` · `400` if `id` is not a number

### 4.4 Update ticket — `PATCH /api/tickets/{id}`

Partial update. Only present fields are changed.

```json
{ "title": "Cannot log in (SSO)", "priority": "CRITICAL", "assignee": null, "version": 2 }
```

| Field | Semantics |
|-------|-----------|
| `title`, `description`, `priority` | If present, validated per `requirements.md §6`; `null` → 400 |
| `assignee` | Present with a value → set; present with `null` or `""` → unassign; absent → unchanged |
| `version` | **Required.** Must equal the current version, else 409 `CONCURRENT_MODIFICATION` |
| `status` | **Not accepted.** If present → 400 `VALIDATION_FAILED` with message "Use the transitions endpoint to change status." |

Responses: `200 OK` + `TicketResponse` · `400` · `404` · `409 TICKET_NOT_EDITABLE` · `409 CONCURRENT_MODIFICATION`

### 4.5 Change status — `POST /api/tickets/{id}/transitions`

```json
{ "targetStatus": "RESOLVED", "version": 2, "note": "Patched SSO redirect URL on staging." }
```

| Field | Semantics |
|-------|-----------|
| `targetStatus` | Required. Valid enum. |
| `version` | Required. Optimistic lock (see PATCH). |
| `note` | **Required** when `targetStatus` is `RESOLVED` or `CANCELLED` (BR-06). Optional for other targets; if present on other targets, ignored and not stored. |

Responses:
- `200 OK` + updated `TicketResponse`
- `400 VALIDATION_FAILED` (missing/unknown `targetStatus`, missing/blank `note` when required)
- `404 TICKET_NOT_FOUND`
- `409 INVALID_STATUS_TRANSITION`:

```json
{
  "title": "Invalid status transition",
  "status": 409,
  "code": "INVALID_STATUS_TRANSITION",
  "detail": "Cannot change status from CLOSED to OPEN.",
  "currentStatus": "CLOSED",
  "requestedStatus": "OPEN",
  "allowedTransitions": []
}
```
- `409 CONCURRENT_MODIFICATION`

### 4.6 List comments — `GET /api/tickets/{id}/comments`

`200 OK` + `CommentResponse[]` ordered by `createdAt` ascending · `404`

### 4.7 Add comment — `POST /api/tickets/{id}/comments`

```json
{ "author": "Rahul", "body": "Reproduced on staging." }
```

Responses: `201 Created` + `CommentResponse` · `400` · `404` · `409 TICKET_NOT_EDITABLE`

### 4.8 Update comment — `PATCH /api/tickets/{id}/comments/{commentId}`

```json
{ "body": "Reproduced on staging and prod." }
```

- Only `body` is accepted; `author` cannot be changed in v1.
- Comment MUST belong to the ticket in the path.

Responses: `200 OK` + `CommentResponse` · `400` · `404` (`TICKET_NOT_FOUND` or comment not on ticket) · `409 TICKET_NOT_EDITABLE`

### 4.9 Delete comment — `DELETE /api/tickets/{id}/comments/{commentId}`

Responses: `204 No Content` · `404` · `409 TICKET_NOT_EDITABLE`

### 4.10 Status history — `GET /api/tickets/{id}/history`

`200 OK` + `[{ "fromStatus": null, "toStatus": "OPEN", "changedAt": "...", "note": null }, { "fromStatus": "IN_PROGRESS", "toStatus": "RESOLVED", "changedAt": "...", "note": "Fixed config." }, ...]` ascending · `404`

## 5. Cross-cutting

- CORS: allow the frontend dev origin (`http://localhost:5173`) via config property, not hard-coded `*`.
- Unknown JSON properties on create/update → ignored, except `status` on PATCH (explicit 400, see 4.4).
- Input strings are trimmed before validation.
